# ADR 002：实体隔离、冻结来源与诚实的效果报告

状态：已实现；最终发布集结果另行封存。记录日期：2026-09-12。

## 问题

注册号能方便地建立真实跨源标签，也很容易把答案泄漏给候选、模型或归并约束。只测进入候选后的准确率会隐藏漏召回；反复根据测试错误改规则则会让“未见测试集”的说法失效。规模数、数据质量和算法收益也必须分别记录。

## 数据边界

A 类主数据来自完整 GLEIF Golden Copy 与 CH 官方七分片。在实际 GB、RA000585、GENERAL、ACTIVE、ISSUED 范围内，用合法登记号和 CH Active 记录交叉核验，排除歧义重复及范围外关系。这是编号完整、可以核验的闭集子集，不代表所有缺编号企业或真实供应商录入噪声。

构建器和 evaluator 保留编号、原文和来源；matcher 只取得 `record_id, record_version_id, source, name, address, city, postcode, country`。前两者是独立随机 opaque ID，不从真实企业编号派生。标识出现在允许文本中时，整个命中字段置 null。候选、评分和 resolver 不使用真值反向查找或由真值构造的 cannot-link。

目录隔离是开发代码契约，不是假装单一开发账号已有操作系统沙箱。实际部署匹配进程时只提供其允许的输入，不挂载 evaluator 或有标识业务存储。

B 类使用官方曾用名派生查询，分别控制 name-only、只含邮编、含复制的当前地址；复制的地址不标为历史地址。C 类为明确标记的合成扰动/治理回放。A、B、C 的结果不得混算；目前没有真实人类复核预算实验。

## 训练、验证与测试

开发集按固定 seed 的真实实体哈希选样并划分 60/20/20，同企业的所有来源、别名和版本共享划分。各文件按独立 record_id 排序，不靠邻接次序暴露真配对。

`evaluation.verify_dataset` 在训练前核验 manifest 文件哈希、路径边界、八列 schema、记录唯一性、实体 split 唯一性和 matcher/truth 覆盖。预检读取测试哈希及 ID/划分元信息，只核验完整性，不计算测试效果。

`run_experiment.py` 只在 train 拟合参数/TF，或加载训练特征 SHA256 与允许 train 一致的冻结模型。在 validation 上运行固定阈值网格，优先最大 F1，其次 precision，再取更大阈值。模型指纹、输入 manifest、依赖锁、代码摘要和阈值写入 frozen_config 后，才对 test 特征评分。输出目录必须新建，失败单独记录，不覆盖已封存结果。

旧 v3 测试在开发期已被查看，之后发现并修复了缺失 country 的候选错误。新 `v4_release` 排除此前全部 50,000 个开发企业，以相同源快照里此前未使用企业的补集作为新测试，train/validation 保持原字节。这是同源未见企业验证，不是时间外推；构建规则与独立性检查见 [发布集说明](../data/V4_RELEASE_HOLDOUT.md)。最终数值仅在 [RESULTS.md](../evaluation/RESULTS.md) 报告。

## 指标与分母

候选 recall 的分母是全部已知真匹配对。条件 pair recall 只在已召回真配对上计算，端到端 recall 则保留所有漏候选。precision/F1、关联记录覆盖、待复核对数和实际候选量一起报告。

当前 A/B 每实体恰有两条跨源记录；`known_pairs` 的全部同实体组合因此正好等于跨源正例。如果未来加入同源别名或多快照，必须明确 pair 的资格范围，不能继续沿用这一假设。候选缩减以两来源记录数乘积为分母，不把跨源链接与源内去重混为一谈。

最终簇计算过度归并簇数、受影响记录、最大错簇、B-cubed precision/recall，要求完整真值覆盖。描述性的 Wilson 区间基于预测对数，不称为独立企业抽样置信区间。Splink 分数未做概率校准，不解释成已经校准的真实业务风险。

B3 只有独立人工标签才能获得额外业务约束；A 主实验未用隐藏注册号补约束，因此无人工标签时 B3 与 B2 相同。治理合成反例用来验证阻止错误传播与撤销，不用于提高真实算法成绩。

## 结果与验证

旧 v3 100k 的测试端到端结果是：精确名称 F1 0.9946、recall 0.9892；模糊名称在验证集选中阈值 1.0，与精确法相同；Splink F1 0.9371、recall 0.8816。该现名称占多数的公开数据上没有观测到模型收益。name-only 曾用名缺少地址证据时仍可能在候选阶段失败；不能只报告带复制地址的容易条件。

`tests/test_evaluation.py` 覆盖漏候选仍进入端到端分母、簇错误、篡改哈希与跨实体划分拒绝。独立审查通过真实实验入口复现并复验了错误哈希、跨 split 实体、覆盖不一致和冻结模型训练来源错误都在结果封存前失败，见 [独立审查](../evaluation/INDEPENDENT_REVIEW.md)。

性能报告记录具体记录数、候选数、各阶段时间、平台和进程峰值内存。100k 指源记录数，不是 100k 成功匹配企业；增量回放使用明确合成的变更，并分别校验分数与成员分区一致性，不把少评分若干对自动等同于业务收益。
