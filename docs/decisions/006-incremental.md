# ADR 006：固定策略的增量闭包与同策略全量兜底

状态：代码已实现；正确性与冻结前提仍须持续分别验证。记录日期：2026-09-12。

增量更新的目标是减少重新评分与归并的范围，同时保持与同一策略全量计算相同的成员分区。它不承担在线学习，身份 UUID 也不用于比较计算等价。

`incremental.refresh_scores` 收集变化记录在旧、新快照中的候选桶，生成受影响的当前候选，只重新评分涉及变化端点的记录对；旧端点产生的评分边被移除。该方法依赖可枚举、固定的成对 blocking 规则和冻结评分函数。当前实现仍需扫描记录的桶键，并不声称免除全量索引扫描。

`incremental.recompute` 将记录新增、删除、调用方显式提供的字段改动、评分边变化以及 must/cannot/suppression 变化作为种子。闭包包含旧、新全部已评分候选关系、约束关系和旧实体簇。候选层保留低分、撤销抑制及此前冲突阻止的边，避免只看已接受边而遗漏重新生效的可能路径。这是保守范围，可能比最小必要闭包大。

在闭包内从零运行同一个 resolver，将未受影响的旧簇与新分区组合。阈值、复核阈值或 `policy_version` 变化直接执行 `new.solve()`；闭包超过 `max_records` 也运行同一 `new.solve()`，不提高阈值或截断候选。模型、标准化、候选规则、TF/全局统计和 resolver 顺序的变化必须由调用方反映到策略版本；一个未更新的字符串本身不能证明这些依赖已冻结。

正确性的关键理由是：闭包收敛后，没有旧、新候选支持关系或约束跨越受影响范围边界，也没有旧实体簇被截成一半。冻结的成对评分和确定顺序因此可在该范围内独立重算。全量与增量比较 canonicalized 成员集合；UUID、边解释的展示顺序均不是等价依据。

当前验收代码位于 `tests/test_incremental.py`：

- 人工难例覆盖撤除 cannot-link 后，以前受阻边重新生效。
- Hypothesis 设置 150 个例子，比较增删节点、候选和约束变化的增量结果与生产 resolver 的全量结果；同时检查零预算全量兜底。
- 阈值改变会触发全量重建。

另有 `tests/test_oracle.py` 的独立小图参考解析器。它用 Boolean Floyd–Warshall 计算全点对可达性，每提出一条支持边就重新计算并检查 cannot-link；不调用生产 `resolve`／`solve`，也不复用生产分组辅助函数。参考实现先通过手工给定分区、状态和冲突证据的难例，随后用于校验生产结果。

2026-09-12 实际运行 `.venv/Scripts/python -m pytest tests/test_oracle.py -q --tb=short --hypothesis-show-statistics`，六项测试通过（1.21 秒）：

- 全量参考对照完成 200 个 Hypothesis 案例，无失败。包含矛盾 must/cannot 的显式失败语义；有效图比较完整成员分区及每条边的端点、分数、状态、原因、冲突证据和处理顺序，并反转输入和端点再次验证确定性。
- 增量参考对照完成 250 个 Hypothesis 案例，无失败。覆盖记录删除／新增、改分、must/cannot/suppression 撤销、cannot 替换和 must 新增；同时比较正常预算与零预算兜底。新约束矛盾时，全量与增量都必须拒绝。
- 手工路径回放验证：撤销 must 后抑制同一自动边，但存在替代路径时实体保持连接；删除替代路径上的记录后实际拆分，孤立无候选记录保留。另验证不能仅保留旧接受边：替换 cannot 后，以前被阻止的高分边可生效。

增量的边解释按展示顺序排列，参考全量按处理顺序排列，因此增量对照比较逐边完整内容和数量，不要求列表展示顺序相同。原有 150 例增量对照仍作为另一组工程验收保留。这些测试检验工程语义和小图等价，不是匹配准确率，也不构成对所有输入的形式化证明；真实规模收益和上游参数冻结须由实际实验分别验证。

`Store.prepare_revision(..., verify_full=True)` 会显式与同策略全量成员分区对照，差异将拒绝发布。真实子进程失败注入已分别在 SQLite 和 PostgreSQL 验证：完整产物落盘但尚未登记时强制终止，旧版本仍可查，重新准备并发布成功，历史不变。可复现脚本、真实运行报告及恢复边界见 ADR 003。

代价是大连通候选桶、密集约束或桥接记录可能扩大闭包到全库。若全量也无法在资源预算内完成，应保留旧发布版本并报告失败。动态 top-k、隐式抽样、全库分位数或重估 TF 的模式必须单独版本化并先按全量评估，不能直接继承本增量承诺。
