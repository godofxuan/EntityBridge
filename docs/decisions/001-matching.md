# ADR 001：固定候选、真实 Splink 评分与独立归并

状态：已实现并验证。记录日期：2026-09-12。

## 问题

企业名称相似不等于企业身份相同，共享注册地址也不能单独决定归并。与此同时，后续源记录变更需要局部刷新，不能让候选集合或模型统计随每个批次隐式变化。必须把候选、评分与业务判断分成可检查的阶段。

## 选择

`candidates.py` 对规范化的跨源记录生成四条固定规则的并集：名称相等、名称前 8 字符相等、邮编加名称前 3 字符相等、地址加邮编相等。已知国家不同时排除；任一国家缺失时不把缺失视为冲突。每条记录能独立枚举自己的桶，记录对去重后保留规则来源。单桶超过 250,000 个跨源组合显式报错，不做 top-k 或抽样截断。

基线共用候选：B0 为标准化精确名称，B1 为 RapidFuzz ratio。B2 调用实际 Splink 4.0.17，以名称和地址的 Jaro–Winkler 比较层、邮编精确层组成模型。城市和国家作为展示/候选信息，不再添加相关性强的重复评分层。地址与邮编本身仍有关联，因此输出称未校准模型分数，不声称条件独立假设完全成立。

Splink 在 train 上估计 u 概率，再按邮编和名称相等分块执行 EM；随机种子与训练行数、训练特征摘要记录在模型元数据。随机匹配先验是按训练侧规模设置的显式假设。未观测的比较层可能使用 Splink 默认参数，清单逐层记录，不能把模型称为全部参数已充分训练。

模型 JSON、训练名称 TF 表和 manifest 一起保存。预测前通过 `register_term_frequency_lookup` 注册该冻结表，新输入不重新估计 TF；新增名称没有训练频率时沿用 Splink 的缺失 TF 回退。模型对象对外返回深拷贝，缓存指纹始终对应内部冻结内容。加载时校验指纹和 Splink 版本。

评分的四条等值 blocking 后附 `eb_requested_pair` 成对过滤，只让请求的 opaque ID 对进入比较。`last_prediction_count` 记录真实输出行数。字段原值、比较层、Bayes factor、记录版本和候选规则随评分保存。评分不会读取登记号、truth_map 或旧的有标识归并结果。

`resolution.py` 独立处理人工 must-link、cannot-link、撤销抑制和分数。先检查显式约束矛盾，再按分数和稳定端点顺序贪心处理边；每次联合前检查整个候选簇的 cannot-link。没有候选只是证据不足，不是不能关联的人工判断。它是确定性的受约束贪心归并，不声称全局最优。

## 代价与效果

固定前缀对完全改名的企业会漏召回；共享地址和常见前缀会产生大桶。单桶预算不限制所有桶的总候选量，EM 训练块也有单独的规模成本。V1 不通过动态近邻索引改善这一点，因为那需要重新设计增量影响分析。

旧 v3 100k 实验中，精确名称的端到端 F1 为 0.9946，当前 Splink 配置为 0.9371。名称一致占绝大多数的公开登记子集没有显示 Splink 增益；继续保留简单基线，模型接入本身不是成果。最终封存结果见 [RESULTS.md](../evaluation/RESULTS.md)。

## 验证

`tests/test_candidates.py` 覆盖并集去重、大桶失败、字段 allowlist 与缺国家；`tests/test_matching.py` 用真实 Splink 拟合并检验保存/重载、固定 TF、对象隔离和请求数等于实际评分数。`scripts/check_compatibility.py` 保存独立的兼容实验产物。

独立审查捕获实际 Splink blocking SQL 的 DuckDB EXPLAIN：旧 v3 100k 输入仍为 4 个 HASH_JOIN，无 CROSS_PRODUCT 或 BLOCKWISE_NL_JOIN。914,580 候选与实际评分行数一致；完整 score 耗时 18.385 秒。该测量只说明这份数据的执行路径，详见 [独立复验](../evaluation/INDEPENDENT_REVIEW.md)。

标准化、特征视图、blocking、模型/TF、阈值或 resolver 版本变化都应触发全量；只有固定策略内的记录或判断变化才进入增量路径。相关决策见 [ADR 006](006-incremental.md)。
