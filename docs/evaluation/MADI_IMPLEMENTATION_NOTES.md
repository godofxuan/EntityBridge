# MaDI 公司实验：拟合前的实现约定

2026-09-15，在首次模型拟合及测试集评分之前补充以下约定。原始协议
`MADI_COMPANIES_PROTOCOL.json` 保持原文；本文件随执行源码一并冻结。

- 候选分别在 Forbes–DBpedia、Forbes–FullContact 中生成，然后取并集。因此 top-k=10 是每个来源对内部的双向检索上限；不生成无标注任务的 DBpedia–FullContact 候选。两种 hybrid 使用同一个仅由训练名称拟合的词表和 IDF。
- 现有 Splink 接口仅接受两个来源，因此对上述两个来源对分别拟合一个模型，仅用各自训练记录，合并评分。阈值统一在合并的验证标签上选择。记录每个模型的指纹与未观测比较层级；不因缺少地址字段跳过或改造其算法。
- 所有方法在同一候选并集上评分，再切回各候选轨道；未知标签不参加混淆矩阵，但会消耗复核预算。没有人为补充负例。
- 主要指标的成对 bootstrap 在 supplied-pairs 轨道上按依赖组件抽样；同一抽样权重同时用于全部模型。组件抽中多次等价于重复该组件内全部已标注对，按固定评分与 ID 次序重算前100对。每次先计算三个 Ditto 种子的平均，再减去逻辑回归，输出百分位95%区间。还计算验证阈值下 F1 与 10FP+FN 差值区间。它不覆盖训练随机性或数据集选择偏差；另外原样列出三个种子。
- 若依赖组件少于2个或最大组件超过50%，不生成误导性区间。小组件有效样本量、边界退化以及部分标注的限制必须在报告中保留。
- 训练配置由协议构造，检查所需类别数；一次 prepare、每个种子一次 train、一次 evaluate，目录不得覆盖。测试特征读取之前写入所有模型、候选器、验证阈值及源码哈希的共同冻结文件。
- 本研究使用已有离线 RoBERTa 基础权重，不使用此前产品任务微调权重；GPU 时段经 RAG 任务释放后使用。来源原表和中间记录留在忽略的本地 artifacts 中，仓库只纳入自有适配器、协议与不含原始记录的汇总。

这是新的公开公司基准研究。历史验收中“当时未提供公司标签”的结论、旧实验数据和旧交付哈希不追溯修改。严谨划分和字段投影与论文榜单不同，不可声称复现或超过论文名次，也不能据此推断工商法律主体或用户 CRM 的生产准确率。
