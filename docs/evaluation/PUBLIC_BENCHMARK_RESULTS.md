# v0.3 公开基准与查询优化结果

本轮补充公开标注对基准、评测协议和查询优化。数据集适配规则在读取测试特征之前确定，模型只使用训练数据，阈值由验证集选择。初次运行发现精确名称基线被允许选择零阈值；修复后进行了明确标记的 `exploratory-replayed` 重放。**这里不是新的未见测试，也不是原论文同协议榜单比较。**

## 数据与标签范围

来源为 DeepMatcher 作者发布的 [数据说明与下载入口](https://github.com/anhaidgroup/deepmatcher/blob/master/Datasets.md)。Fodors–Zagats 是餐馆记录，DBLP–ACM 是论文记录；它们用来诊断跨领域的记录匹配流程，不是企业法人身份的替代金标。适配与许可边界见 [公开数据集目录](../data/PUBLIC_BENCHMARKS.md)。

| 数据集 | 来源记录 | 原始标注对 / 正例 | 本轮测试记录 | 测试标注对 / 正例 |
|---|---:|---:|---:|---:|
| Fodors–Zagats | 864 | 946 / 110 | 154 | 55 / 20 |
| DBLP–ACM | 4,910 | 12,363 / 2,220 | 971 | 827 / 444 |

原始协议按配对切分，Fodors–Zagats 有 279 条记录、DBLP–ACM 有 2,861 条记录出现在多个划分。本轮按照正标签连通分量划分已知实体，并丢弃跨划分负例，分别保留训练/验证/测试 413/49/55 与 5,411/758/827 对。所有原始文件 SHA 固定；未知配对始终未知，不构造完整聚类真值。

重划分丢弃负例会改变各划分的匹配比例。结果只描述当前标注样本，不能估计全部可能配对的准确率或真实业务概率。DBLP 只将标题映射到 name，作者和年份没有伪装成地址特征。

## 冻结的比较方法

- 评分器：精确名称、模糊名称、现有 Splink 企业配置，以及新增的字段相似度 Logistic Regression。后者只有训练标签进入拟合，使用固定 C=1，没有在 test 上调参；当前是基准评分器，没有接入默认自动合并策略。
- 候选：固定 blocking；训练集冻结的字符 TF-IDF 混合候选（k=10，最小相似度0.2）；直接给定标注对的分类诊断。第三种不是生产检索，不能用它证明召回能力。
- 决策：在验证集最小化假设成本 `10×FP + 1×FN`，同成本优先全部拒绝、再优先更高阈值。精确名称只能取阈值1或全部拒绝。10:1只是明确的评测场景，不是测得的业务损失。
- 评分：候选已知正例召回、已标注对 P/R/F1、AP与PR曲线、未知预测覆盖、概率Brier/ECE、复核预算曲线和整组 bootstrap；详见 [评测协议](EVALUATION_PROTOCOL.md)。

表中的 P/R/F1 按该数据集全部测试标签计算，漏出候选集的已知正例仍计为 FN；未知对不进入混淆矩阵。已知标签成本为 `10×FP + FN`，未知预测不计入，因此它不是所有输出的业务风险估计。成本随标签数量变化，也不能直接跨数据集比较。

每种评分器在每条候选轨道上分别选择验证阈值。固定候选与混合候选之间的自动匹配结果差异同时包含候选和阈值变化，不能当作只替换召回器的消融实验。AP、PR-AUC、Brier 与 ECE 只基于各轨道已标注且有评分的候选；候选范围和正负比例不同，跨轨道数值差不能直接解释为区分能力或校准改善。概率指标只诊断当前标签样本，Splink 与 Logistic 输出尚未针对部署流量校准。

## 不能从这些数字推出什么

Fodors–Zagats 的混合候选加 Splink 在55个标注对上得到20 TP、0 FP、0 FN。它只有20个正例、16个依赖组，按组大小计算的均衡诊断 `N²/Σn_g²` 约4.33；这不是真实独立样本量的证明。经验 bootstrap 的 `[1,1]` 退化区间无法生成没有观察到的错误，不能证明总体表现完美。报告保留原始数值，并附带边界退化和小样本提示。

Fodors–Zagats 固定候选中只有18个已标注正例，没有已标注负例，因此 AP=1 本身不能证明区分能力。混合候选扩大到107对，其中21对有标签、86对未知；混合 fuzzy 接受了其中42个未知对。表中的 precision 没有评价这些对，不能写成“全部输出有95.24%正确率”。复核预算曲线已将未知候选计入人工预算，但只报告已知正例捕获，没有测量人时或实际节省比例。

DBLP–ACM 的候选数从820增至4,285，已知正例候选召回由434/444增至444/444，混合候选中有3,468对未知。这说明本样本的已知正例覆盖提高，不代表找全所有真实匹配，也未带来相应的自动匹配收益：监督 Logistic 固定候选 F1=0.9398，混合候选为0.9326。固定候选 fuzzy 的 F1=0.9362，与 Logistic 的差约0.0036；这里没有计算按相同组重采样的方法差值区间，不能宣称显著优于 fuzzy。

在预声明的10:1成本下，DBLP–ACM 固定候选的 Splink 为20 FP、45 FN，已知标签成本245；Logistic 为23 FP、30 FN，成本260。Splink 的成本更低而 F1 更低，说明两种目标对误合并与漏合并的权重不同。报告保留全部预声明方法，不根据已看过的测试结果更换目标、选择新超参数或上线策略。

现有 Splink 配置在缺失地址/邮编的跨领域数据上有无法估计的层级，使用其默认参数；该情况保存在模型元数据，不能描述成充分训练的领域专用模型。

首次v1的 exact 报告因允许零阈值不满足“精确名称法”定义，保留用于追溯，不作该基线成绩。v2固定这一语义；其他三种评分器的 TP/FP/FN/TN 与v1完全一致。v1/v2的协议、配置、原始数值和实际执行源码包分别封存，没有覆盖旧结果。

## 查询优化的成对实验

同一份10,000条合成记录、5,000个实体、11,467,079字节冻结产物，四类查询各25对、交替执行先后顺序，所有返回值逐项一致。下表是SQLite、本机进程及操作系统缓存已热的耗时；不是生产网络吞吐，也不是PostgreSQL加速倍数。

| 查询 | 旧版 p50 / p95 ms | 查询投影 p50 / p95 ms |
|---|---:|---:|
| 第一页 | 64.07 / 67.42 | 2.09 / 2.68 |
| 深页 | 60.12 / 78.78 | 2.09 / 2.68 |
| 别名包含 | 72.75 / 94.86 | 17.22 / 22.04 |
| 无匹配 | 74.44 / 84.97 | 13.61 / 16.11 |

稳定投影100次查询完整JSON读取为零。旧版本首次回填另花约495 ms、一次完整文件逻辑读取。它不是物理磁盘读量，不能据此推断硬盘吞吐。准备与发布增加索引写入和一致性验证成本；名称包含搜索仍需检查精简名称值，深OFFSET仍有跳过成本。设计及维护接口见 [ADR 008](../decisions/008-query-projection.md)。

## 复现

```sh
python scripts/fetch_benchmarks.py --dataset all
python scripts/run_public_benchmark.py --dataset artifacts/benchmarks/v1/fodors_zagats --output artifacts/reports/my_fodors --test-status exploratory-replayed
python scripts/run_public_benchmark.py --dataset artifacts/benchmarks/v1/dblp_acm --output artifacts/reports/my_dblp --test-status exploratory-replayed
```

上述公开test已在此文展示，所以复现用 exploratory-replayed。真正首次预注册的新数据实验才使用 first-predeclared。脚本拒绝覆盖已有输出目录。源数据只保存在本地，公开仓库仅分发代码、数值和来源哈希。
